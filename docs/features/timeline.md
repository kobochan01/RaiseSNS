# 機能定義書: タイムライン

## 概要

全ユーザーの投稿を表示する「全体タイムライン」と、フォロー中ユーザーの投稿のみを表示する「フォロー中タイムライン」を、タブで切り替えて表示する機能。

## 入力/出力

### 全体タイムライン取得

**入力**

| 項目 | 型/形式 | 必須 | 説明 |
|------|---------|------|------|
| cursor / page | 文字列/数値 | 任意 | ページング用の位置情報 |
| limit | 数値 | 任意 | 取得件数（デフォルト値を設ける） |

**出力**

| 項目 | 説明 |
|------|------|
| posts | 投稿一覧（新着順）。各投稿にauthor情報・body・image_url・likeCount・commentCount・isLikedByMeを含む |
| nextCursor | 次ページ取得用の情報 |

### フォロー中タイムライン取得

**入力**

| 項目 | 型/形式 | 必須 | 説明 |
|------|---------|------|------|
| cursor / page | 文字列/数値 | 任意 | ページング用の位置情報 |
| limit | 数値 | 任意 | 取得件数 |

**出力**: 全体タイムラインと同様（対象がフォロー中ユーザーの投稿に限定される）

### 新着投稿の取得（リアルタイム更新用）

**入力**

| 項目 | 型/形式 | 必須 | 説明 |
|------|---------|------|------|
| sinceId | 数値 | 必須 | この投稿IDより新しい投稿のみを対象にする |

**出力**: 全体タイムラインと同様（`sinceId`より新しい投稿のみを新着順で返す。`nextCursor`は使用しない）

フロントエンドは30秒間隔でこのAPIをポーリングし、新着投稿があれば通知バナーを表示する。ページが非表示の間はポーリングを行わない。

## バリデーションルール

| 項目 | ルール |
|------|--------|
| 取得件数 | 1回のリクエストで取得できる件数の上限を設ける（例: 最大50件） |
| フォロー中タイムライン | フォロー中ユーザーが0人の場合は空一覧を返す |
| 表示順 | 新着順（created_at の降順） |
| 認可 | ログイン中のユーザーのみ取得可能 |
