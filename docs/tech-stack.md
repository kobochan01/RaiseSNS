## AWS 本番環境インフラ（暫定）

> AWS上にサーバーを構築するかどうか自体は未確定だが、構築する場合の構成として ALB・EC2・RDS を用いる前提で先行して設計しておく。EC2の台数（単一 or オートスケーリング）は未定のため、スケール可能な構成として記載する。

| 役割 | 技術 |
|------|------|
| ロードバランサー | AWS ALB (Application Load Balancer) |
| サーバー | AWS EC2（台数未定。オートスケーリンググループ配下に1台〜を想定） |
| リバースプロキシ | nginx（EC2上、React配信 + `/api/**` をSpring Bootへプロキシ） |
| データベース | AWS RDS (PostgreSQL) |
| 画像ストレージ | AWS S3 |
| ネットワーク | AWS VPC |

### リクエストの流れ

| パス | 処理 |
|------|------|
| `/*` | ALB が EC2 群へ振り分け、nginx が React のビルド済みファイルを返す |
| `/api/*` | ALB → nginx → Spring Boot（:8080）へリバースプロキシ |
| Spring Boot → RDS | プライベートサブネット内の PostgreSQL に接続 |
| Spring Boot → S3 | 画像アップロード時にAPI経由（または署名付きURL）でS3へ保存 |

### ネットワーク構成

| リソース | 用途 |
|----------|------|
| VPC | 全リソースを格納するプライベートネットワーク |
| パブリックサブネット（2 AZ） | ALB・EC2 を配置 |
| プライベートサブネット（2 AZ） | RDS を配置。インターネットからの直接アクセス不可 |
| インターネットゲートウェイ | ALB へのインバウンドを許可 |

### セキュリティグループ

| SG | 許可インバウンド |
|----|----------------|
| ALB SG | HTTPS (443)・HTTP (80) — インターネットから |
| EC2 SG | アプリポート — ALB SG からのみ／SSH (22) — 自分のIPのみ |
| RDS SG | PostgreSQL (5432) — EC2 SG からのみ |

> 台数・スケーリングポリシー・Terraform構成などの詳細設計は、AWS上に構築すると決まった時点で改めて詰める。
